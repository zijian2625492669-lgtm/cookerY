# cookerY v0.2：共用账号

当前使用一个 Supabase Auth 账号，供两人共同登录。前台支持完整邮箱或短账号；短账号会补全为 `账号@cook.com`。填写后台创建该用户时设置的密码即可，无需收验证码。

## 账号和权限

共用账号已由用户在 Supabase 后台创建并自动确认，并已加入 public.members。数据库与图片桶仍通过成员权限控制访问，两台设备可以同时使用同一账号。新增后台用户不会自动获得菜谱权限，日常无需再次维护白名单。

登录状态保存在各自浏览器。退出只作用于当前设备，不会把另一台设备踢出。忘记密码需通过 Supabase 管理端重设；邮箱若仅作登录标识，不应依赖邮件找回。

「我的」可以修改密码，需要先输入当前密码。一个账号共用时无法区分是谁添加或修改了菜谱，创建人显示为「我们俩」。

## 部署和使用

main 的 GitHub Actions 自动部署到 [cookerY](https://zijian2625492669-lgtm.github.io/cookerY/)。前端已使用本项目的浏览器公开配置；现有 GitHub Actions Variables 可继续覆盖默认值。无需在前端放管理员密钥。

首次云端菜谱本为空；在原来保存了菜谱的浏览器打开「我的 → 导入本机旧菜谱」。原始本地数据保留，重复导入按旧 ID 跳过，不覆盖云端。另一个浏览器新记但 ID 相同的旧原型菜谱也会跳过，请核对后单独新增。

列表每 30 秒、重新聚焦或联网时刷新。两台设备同时编辑同一道菜时，旧版本保存会被拒绝并提示返回详情重新确认。保存失败会保留当前编辑内容，整份菜谱的关系数据在数据库事务内保存。

封面上传前压到 1600px / 1MB 内，私有图片使用一小时签名地址，刷新列表会更新。替换或删除菜谱后会尝试清理旧封面；网络中断可能留下未引用的图片。步骤图片留待下一步。

## 验证

```bash
npm ci
npm run build
npx playwright install chromium
npm test
# 本环境已有 Chromium 时：CHROMIUM_PATH=/usr/bin/chromium npm test
```

浏览器测试使用模拟 API，验证短账号和完整邮箱登录、保存失败重试、五段菜谱、封面上传、删除失败恢复。tests/database.sql 在真实项目事务内验证 RLS、共享编辑、创建人保护、重复导入、失败回滚和级联删除，结束后回滚全部测试账号与数据。

supabase/schema.sql 是空项目初始化的完整结构快照，已在本项目应用；不要在已有表的项目重复整段运行。真实密码登录需要使用你设置的密码在正式页面体验；发布验证不需要收集或重置该密码。
